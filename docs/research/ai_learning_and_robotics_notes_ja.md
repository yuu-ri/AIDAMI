## 1. 議論を貫く中心的な考え

学習は、経験から関係や規則性を抽出し、内部構造に符号化する過程として捉えられる。その符号化を新しい入力に適用することで、認識・予測・行動が可能になる。

```text
経験 → 関係の学習と符号化 → 新しい状況での予測・判断 → フィードバック
```

このセッションで特に重要だった直観は、次の表現である。

> 小さな構造の中に、大きな世界の構造を表現できることが、学習の力である。

これは世界の細部をすべて複製するという意味ではない。多くの経験で再利用できる関係を、比較的コンパクトに保持するという意味である。

## 2. 学習の目的関数は何か

### 2.1 人間について断定できないこと

人間の学習全体を説明する単一の目的関数は、この議論では確定していない。また「単一の目的関数が証明されていない」ことから「必ず複数の目的関数を使う」とも結論できない。

パターンを区別する能力は、目標に向けた学習の基礎条件になり得る。ただし、必要な能力であることと、最終的に最適化される量であることは別である。

例えば、温度調節には温度を区別する能力が必要だが、調節の目的関数は目標温度からの偏差として定義できる。

### 2.2 AIに具体的な目的を与えることはできる

予測学習なら、例えば次を最小化する。

```
L(θ) = -E[ log p_θ(x_{t+1} | h_t, a_t) ]
```

- `h_t`：時刻 `t` までの経験。
- `a_t`：行動。受動的な学習では省略できる。
- `x_{t+1}`：実際に得られた次の観察。
- `p_θ`：モデルが予測する確率分布。

意味は「実際に起こった結果に、適切な確率を与えられるようにする」である。

数値を一つ予測する場合は、二乗誤差も使える。

```
L = E[ ‖x̂ - x‖² ]
```

「予測と経験の距離を縮める」は有用な直観だが、すべての損失が厳密な距離ではない。KLダイバージェンスも通常の意味の距離ではない。

### 2.3 予測の正確さと行動の望ましさは別

「明日は空腹になる」と正確に予測できても、空腹を望むわけではない。予測損失だけでは、何を実現したいかは決まらない。

また、予測しやすい経験だけを選ぶと、探索が進まなくなる可能性がある。行動を選ぶには、目的達成・情報獲得・費用などを別途設計する必要がある。

## 3. 対象の式を知らなくても学習できる理由

真の関係が `y = f(x)` であっても、学習者は `f` の式を知る必要がない。

1. 自分のモデル `f̂_θ(x)` で予測する。
2. 実際の結果 `y` を観察する。
3. 予測との違いを評価する。
4. 自分のモデルを更新する。

必要なのは、観察可能な経験、評価基準、更新機構である。モデルのパラメータで微分する際にも、未知の真の関数の式は不要である。

ただし、アルゴリズムを定義できることと、任意の対象を必ず学べることは違う。観測不足、ノイズ、容量不足、最適化の失敗などは残る。

## 4. モデル・状態・学習アルゴリズムの区別

会話中の「モデル」という言葉には複数の意味があったため、次のように整理する。

| 記号・概念 | 意味 | 例 |
|---|---|---|
| `S` | 計算構造 | 接続、層、非線形演算、記憶機構 |
| `θ` | 学習されるパラメータ | 重み、バイアス |
| `z_t` | 実行中の内部状態 | 直前までの入力に関する情報 |
| `L` | 評価基準 | 予測損失 |
| `U` | 更新規則 | 勾配に基づくパラメータ更新 |

```
M_t     = (S_t, θ_t)
M_{t+1} = U(M_t, 経験, フィードバック)
```

統一的な学習システムという構想は、例えば「構造と更新規則を共通に保ち、状態とパラメータを経験によって変える」と表現できる。

ただし、統一システムであっても、内部の各部分が同じ演算をする必要はない。異なる入力処理や専門モジュールを、共通のシステム内に持たせられる。

## 5. 非線形関係を学ぶネットワーク

### 5.1 加重和だけでは足りない

```
h = W₁x + b₁
ŷ = W₂h + b₂
```

を合成しても、全体は一つのアフィン変換になる。層を増やすだけでは一般の非線形関係を表現できない。

非線形関数 `σ` を挟む。

```
h = σ(W₁x + b₁)
ŷ = W₂h + b₂
```

ReLUやtanhなどを使い、複数の単元を組み合わせることで、曲線や複雑な関係を表現する。有限のReLUネットワークは区分線形なので、例えば平方関数は有限区間上で近似する、という理解が正確である。

### 5.2 時間系列の基本モデル

```
z_t      = tanh(A z_{t-1} + B x_t + b)
x̂_{t+1} = C z_t + d
```

これは一層の循環隠れ層と出力層を持つ基本例である。

- 非線形変換が、複雑な関係を表す。
- 内部状態が、過去の情報を次へ伝える。
- 重みが、何を保ち何を予測に使うかを調整する。

千時刻処理しても、独立した千層を用意するわけではない。同じ計算とパラメータを時間方向に繰り返し使用する。

これは説明用の出発点であり、すべての課題に単純な循環網が最適という提案ではない。

### 5.3 層数・幅・位幅は別の設計変数

| 設計変数 | 決めるもの |
|---|---|
| 層数 | 変換や関係の組合せの段数 |
| 各層の次元 | 並列に表現できる特徴の数 |
| 状態次元 | 過去を保持する内部表現の容量 |
| 数値の位幅 | 各値の精度・範囲・保存容量 |

前層が `n` 次元、次層が `m` 次元なら、全結合層の重みは `m × n`、バイアスは `m` 個となる。

異なる層で激活関数や次元が違ってもよい。同一の循環層は通常、時間方向に計算規則を共有する。オンライン学習を行う場合は、その共有パラメータ自体も更新される。

## 6. 勾配降下法

勾配降下は「誤差が増える方向を調べ、その逆へ少し進む」方法である。

```
θ_new = θ_old - η ∇_θ L
```

- `∇_θ L`：各パラメータが誤差に与える局所的な影響。
- `η`：学習率、つまり一歩の大きさ。

一変数では負の導関数の方向に進む。「負の逆数」ではない。

例として `ŷ = wx`、観察が `x = 2, y = 6` のとき、

```
L(w)  = (2w - 6)²
L'(w) = 4(2w - 6)
```

`w = 1`、学習率0.1なら、更新後は `w = 2.6`。反復すると3に近づく。

逆伝播は勾配を効率的に計算する方法であり、勾配降下はそれを使って更新する方法である。一般のネットワークでは最適解への到達は自動的に保証されない。

## 7. 関係の符号化と圧縮

多数の観察が `y = 2x + 1` に従うなら、観察を一件ずつ保存する代わりに、式と係数で表せる。これが規則性による圧縮の例である。

神経ネットワークでは関係が多数の重みに分散して表現されることがある。ただし、学習したから必ず圧縮されるわけではなく、大きなネットワークが標本を記憶している場合もある。

### 7.1 圧縮に影響するもの

| 要因 | 影響 |
|---|---|
| 構造 | どの関係を少ないパラメータで表せるか |
| 学習アルゴリズム | 良い表現を見つける速さと到達点 |
| データ | 規則性、ノイズ、偏り、網羅性 |
| 目的関数 | 精度と複雑さの何を優先するか |
| 許容誤差 | どこまで細部を残す必要があるか |
| 数値精度 | パラメータ一つに必要なビット数 |

予測誤差と符号長を組み合わせる設計は、次のように書ける。

```
min [ 予測誤差 + λ × 符号長 ]
```

符号長には必要な構造・パラメータを含める。経験全体を復元する圧縮として評価するなら、説明しきれない残差の情報量も必要になる。

### 7.2 モデルだけでは使えない

重みは学習ノートに似ている。ノートを利用するには、その書き方を解釈する規則が必要である。

実際の実行には、構造・演算仕様・重み形式・入力出力の変換・実行エンジンが必要になる。推論は学習過程の逆操作という意味の単純な「復号」ではなく、学習された関係を新しい入力に適用する計算である。

## 8. 世界と内部構造の対応は証明されているか

外部の変化を `F`、内部の変化を `G`、対応づけを `E` とすると、理想的な関係は、

```
E ∘ F ≈ G ∘ E
```

となる。外で変化してから符号化することと、符号化してから内部で変化を推演することが対応する。

厳密な等式が成り立ち、`E` が適切な可逆性・連続性を持つ場合、力学系の共役という数学的概念につながる。

関連研究には、循環網による有限時間軌道の近似、回声状態ネットワークによる埋め込み・共役、特定の学習法の近似保証がある。ただし、次の三つは区別しなければならない。

1. その関係を表せるネットワークが存在する。
2. 観察からその関係を識別できる。
3. 実際の訓練がそれを見つける。

存在定理だけで、観測の十分性や訓練成功まで証明されたことにはならない。また、対象は条件を満たす力学系であり「現実世界全体と任意のネットワークが同構」という結論ではない。

## 9. 通用性と専門化

対象の具体的な規則が不明でも、入力の構造を一部知っている場合がある。画像には空間配置、音には時間変化、言語には順序や依存関係がある。

これを設計に利用すると、データ効率や計算効率が良くなる可能性がある。一方、専門的な仮定が対象に合わなければ制約になる。

有力な構想は、専用の入力処理と共通の内部表現を組み合わせることである。言葉の「犬」、犬の画像、鳴き声の対応も学べる。ただし、別々の表現は単に並べるだけでは意味が整列しない。対応データや共同学習などが必要になる。

人への類推としては、既有知識や理解の不足が違えば、同じ内容でも有効な説明経路が違う可能性がある。ただし人工ネットワークの比較だけで、人間の学習法の優劣が実証されたことにはならない。

### ベイズ更新との関係

```
P(H | E) = [ P(E | H) × P(H) ] / P(E)
```

既有知識は先験的な信念、経験は証拠、更新後の信念は事後確率としてモデル化できる。先験確率だけでは更新できず、尤度も必要である。これは一つの数理的記述であり、すべての人間やネットワークが厳密にベイズ計算するとの断定ではない。

## 10. ロボットの基本方針

このセッションで採用した方向は、次の分担である。

> クラウドで自然言語を理解し、本体で視覚認識・追跡・制御を継続する。

| クラウド | ロボット本体 |
|---|---|
| 意図理解、曖昧さの解消、上位計画 | 検出、追跡、位置推定、移動・操作 |
| 新規指示や失敗時の再検討 | 実行状態の管理、障害物対応、停止 |

指示開始時に数秒待つ構成は検討できるが、遅延は保証されない。クラウド応答のP50・P95とタイムアウトを測り、毎フレームの処理や即時停止をクラウドに依存させない。

### 10.1 自然言語で指定した物体を探す

「赤いカップを探して」のような課題は、開放語彙物体検出・視覚グラウンディングに相当する。基本的な検出のために、本体へ会話用の大規模言語モデルを追加する必要はない。

候補として議論したモデル：

- Grounding DINO：文字記述から候補物体を検出。
- YOLO-World：開放語彙検出と速度重視の構成を検討。
- Florence-2-base：短句と画像領域の対応などを扱う候補。

「カップ」と「パソコンの左側のカップ」では難度が異なる。属性や位置関係が確実に扱えるとは限らず、候補検出後の追加判定・ユーザー確認を設ける。入力言語の対応も検証する。

## 11. ROS 2上の本体視覚サービス

視覚Agentは、検出モデルを呼ぶだけでなく、目標・履歴・再試行を管理する常駐サービスとして構成する。本体で大規模言語モデルを動かすことは必須ではない。

| ノード | 主な責務 |
|---|---|
| `cloud_bridge` | クラウドとの通信、構造化タスクの受信 |
| `task_manager` | 検証、調停、進行状態管理 |
| `vision_agent` | 文字指定検出、追跡、再探索 |
| `camera_driver` | 画像・深度・カメラ情報の発行 |
| ナビゲーション／操作ノード | 移動、視点変更、アーム動作 |
| 底層制御 | 実行器の監視、限速、停止 |

| ROS 2インターフェース | 用途 |
|---|---|
| Topic | 画像、検出結果、継続的な位置更新 |
| Service | 短い状態照会、設定変更 |
| Action | 探索・追跡・移動など、進捗と取消を伴うタスク |

クラウドは例えば次の高位タスクを渡す。

```json
{
  "task_id": "find-001",
  "action": "find_and_track",
  "target": "red cup",
  "constraints": [{"relation": "on", "reference": "table"}]
}
```

本体は受付応答と進捗・結果を分ける。画像座標には画像サイズ・座標規約・時刻・フレームを付け、ロボット座標を返す場合は深度や校正、座標変換を用いる。

### 状態の保存

- メモリ：追跡ID、直近位置、消失フレーム数、短期履歴。
- 永続保存：必要なタスク情報、設定、イベント記録。
- 再起動後：古い位置を現位置とみなさず、再検出で確認。

モデル呼出しが無状態でも、周辺のAgentプログラムは状態を持てる。クラウドAgentも同様である。状態更新は、重みを変えるオンライン学習とは別である。

常駐運用にはプロセス監視、カメラ切断時の扱い、タスク取消、タイムアウト、リソース上限も必要になる。ROS 2の通信方式だけで永続化や安全性が完成するわけではない。

## 12. 農業・看護などへの領域適応

通用的な能力の上に、必要な部分だけを特化する。

| 不足する能力 | 対応例 |
|---|---|
| 領域知識・作業手順 | 知識ベース、指示、ルール |
| 特有の対象を見分ける能力 | 現場データによる感知モデルの微調整 |
| 特有の動作 | 本体に合った制御・模倣学習など |

農業では品種、成熟度、遮蔽、採取力などが問題になる。看護では転倒と横臥の区別、個人差、接触動作などが問題になる。知識の追加だけで身体技能を獲得できるわけではない。

まず既存能力を実環境で評価し、不足部分を特定する。安全に関わる判断や動作を、単一の視覚推定だけに依存させない。

## 13. 計算機・GPU・FPGAの選び方

### 13.1 実行場所とモデルの能力は別

同じモデルを同じ数値条件で実行するなら、CPU・GPU・FPGAで意図する計算結果は同じである。違いは主に速度、消費電力、記憶容量、開発費、入出力の統合である。

- GPU：大きな行列計算や学習、開発用の柔軟性。
- FPGA：特定の処理を回路に合わせ、低遅延や効率を狙う。
- CPU：小規模処理、制御、一般的なソフトウェア。

FPGAでも重みを学習・更新する実装は存在する。ただし、重みの更新と、学習による回路構造の自律的な再構成は別である。大規模モデルでは計算器の再利用と外部メモリが必要で、全接続を独立回路として展開できるとは限らない。

### 13.2 現在の開発PC

| 部品 | セッションで確認した構成 |
|---|---|
| 機種 | Dell Precision 7560 |
| CPU | Core i9-11950H |
| GPU | RTX A4000 Laptop、8GB |
| メモリ | 32GB |
| SSD | 512GB |

この構成は、クラウド言語理解＋ローカル視覚検出・追跡の試作を開始するのに妥当である。実際のモデル・解像度・並行処理で測定する必要がある。SSDはデータや録画が増えると不足しやすい。

**訂正点：このA4000はノート版8GBであり、デスクトップ版A4000の16GB仕様と混同しない。**

### 13.3 開発PCと本体の性能差

開発機が必ず本体より大幅に高性能である必要はない。重い学習や仮想環境を同時に動かす場合に、追加の性能が有用になる。

このプロジェクトでは、まず現有PCで一連の処理を完成させ、本体候補で実測する。Jetson Orin Nano／NXは電力・寸法・統合を重視する選択肢であり、ワークステーションGPUの単純な性能上位互換ではない。

比較ではFP32、FP16、INT8、疎性の条件を揃える。TOPSとTFLOPSをそのまま比較しない。共有メモリ容量と独立VRAM容量も区別する。

### 13.4 外付けGPUという選択肢

複数の既存ノートPCを活用する案として、Khadas Mind GraphicsのRTX 4060 Ti 16GB版を検討した。

- ホスト側に対応するThunderbolt／PCIeトンネリング可能なUSB4などが必要。
- USB-Cという端子形状だけでは接続可否は判断できない。
- 8GB版との取り違えを避ける。
- OS、ドライバ、ホストとの実機互換性を確認する。
- 外付け接続の転送帯域が性能に影響する。
- 内蔵GPUと外付けGPUのVRAMが自動的に合算されるわけではない。

モデルをGPU上に保持し、画像と小さな結果だけを転送する構成は検討しやすい。ただし、購入判断は価格と対象ノートの型番を確認してから行う。

## 14. 次に実装する最小構成

1. 現有PCで、保存画像＋短い文字指定から対象枠を出す。
2. カメラ一台を接続し、検出と追跡を分ける。
3. ROS 2ノードとして公開し、時刻付き結果を発行する。
4. 探索・追跡をAction化し、取消・時間切れ・対象消失を扱う。
5. クラウドから構造化タスクを渡す。
6. 実環境で計測してから本体へ移す。

計測する項目：

- 指示した物体を正しく選べた割合、見逃し・誤検出。
- 複数候補時に誤って一つを選ばないか。
- 検出遅延、追跡更新頻度、結果の古さ。
- GPUメモリ、CPU負荷、温度、継続消費電力。
- クラウドの典型・遅い応答時間、通信断時の挙動。

## 15. 未解決の問い

- 予測損失だけで、望ましい内部関係がどこまで形成されるか。
- 固定構造と構造適応を、どの条件で使い分けるべきか。
- 表現の圧縮を、精度・計算費用・符号長のどれで評価するか。
- 画像や言語の統計的な対応を、実世界の因果関係とどう区別するか。
- 人間の学習との対応を、比喩から実験可能な仮説へどう進めるか。
